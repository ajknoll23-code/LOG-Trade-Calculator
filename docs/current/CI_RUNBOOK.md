# Batch 5 CI Stabilization — Release-Freeze-Aware Regression

Date: 2026-08-29

## Executive summary

The third GitHub `Repo Regression Checks` run proved the new active workflow path and rolling-artifact self-heal were functioning correctly. The run refreshed `scripts/player_positions.json` and `data/free_agents.json`, passed free-agent source parity, passed deep runtime parity, and then failed because `scripts/production_history_components.json` no longer exactly matched a regeneration from the current historical source inputs.

That failure revealed a release-boundary bug in the regression design: `production_history_components.json` is part of the already-deployed IDP V1 release lineage and must remain frozen with the approved candidate/patch/baseline. Upstream historical source snapshots can legitimately refresh later. A general repo validation workflow must not silently turn such a refresh into a new model release.

## Final state model

### Rolling deterministic derived state

These may be regenerated inside a manual validation runner:

- `free-agent-board.html`
- `scripts/player_positions.json`
- `data/free_agents.json`

They are derived from current committed repo inputs and should track those current inputs.

### Frozen deployed IDP V1 release evidence

These must not be regenerated by general repo maintenance:

- `scripts/production_history_components.json`
- `scripts/idp_v1_model_delta_transport_candidate.json`
- `scripts/idp_v1_prod_mult_patch.json`
- `scripts/prod_mult_pre_v1_baseline.json`

New file `scripts/idp_v1_release_manifest.json` SHA256-protects those four artifacts and records the source/code snapshot hashes used for release provenance.

## Regression behavior

`repo_regression_checks.py` now:

1. verifies the frozen release artifacts exactly match their release-manifest hashes;
2. computes current historical history output for diagnostics;
3. if all release source/code files are still byte-identical, requires the generator to reproduce the frozen history exactly;
4. if current source/code files have legitimately changed, reports that drift as `INFO` and keeps the deployed release frozen;
5. validates the approved frozen V1 candidate and patch rather than rebuilding a new release candidate from mutable current inputs;
6. continues to validate the actual deployed `index.html` against the approved 320-change patch.

- made `scripts/player_positions.json` stale;

A second derived-state refresh was a no-op, proving idempotence.
