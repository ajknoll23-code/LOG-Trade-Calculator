# QF11 V33 — Optional Google Apps Script HtmlService iframe transport (disabled source)

This is an **alternative** to V32 `fetch()` POST. Google Apps Script ContentService redirects responses to googleusercontent.com; cross-origin browser acknowledgments may fail. Google Apps Script HtmlService permits `google.script.run` RPC **inside the Apps Script-rendered iframe**, with callbacks capable of distinguishing accepted and rejected replies. The iframe can be embedded in the calculator Market Research tab; the voting UI remains there rather than moving to a separate public site.

**No service is deployed. No page is modified. No participants are authorized.** V33 adds only `frame-host.gs`, `pilot-frame.html`, `frame-host.test.js`, and this document. The V32 direct-post bridge stays disabled as a fallback research route, not an active solution.

Before activation the private Apps Script project must contain the existing V31 `collector.gs` and these two new host files. When deployed the HTML file name is `pilot-frame` (source `pilot-frame.html`); the supplementary V31 sheet configuration must match exactly. All seven independent script-property gates remain false by default. The project **must not** reuse V1’s Google Script, spreadsheet or Market Value aggregator.

`doGet` renders no ballot unless all seven gated properties are exactly true. Valid private invitation tokens are verified using V31 HMAC against an allowlist; **the real trio is not displayed without a valid token**. Ranked choices, consent checks, three proposed multiple-choice comprehension answers, and a one-time submission use `google.script.run`. V31 `qf11v2Handle_` remains the sole authorized response writer under a script lock. Q4 must be reviewed outside this form by the moderator. No raw tokens or Q4 open-ended responses are stored in the spreadsheet. No arbitrary parents can trigger the UX under ordinary browser rules because client checks `document.referrer` origin, but this is **not a server-authenticated origin check**.

**Security caveat:** embedding the HtmlService page requires `setXFrameOptionsMode(ALLOWALL)`, which can increase clickjacking exposure. Browser-origin, referee, iframe behavior, Apps Script permissions, session-token handling and authorization must be empirically checked in the actual deployment. The referrer guard is defense in depth only and can fail closed for privacy-preserving browsers. Do not promote to an operational system on tests alone. An empty/missing referrer should block intake. The operator must independently review an actual consent notice, age screening, one person per slot, study wording/Q4 scoring, deletion trigger, exports/logs/backups and participant privacy.

**Owner decision still needed:** separate real-pilot activation authorization, after independent instrument/privacy/security review and dummy-only browser E2E tests. The first 12-person cohort tests **comprehension only** and is not Market Value or Fundamental Value calibration evidence.
